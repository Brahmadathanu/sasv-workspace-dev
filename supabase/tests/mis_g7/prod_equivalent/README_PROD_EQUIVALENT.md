# Production-equivalent acceptance (isolated, free, no production writes)

1. **Capture (read-only, by someone with authorized read access):**
   `MIS_G7_PROD_RO_URL='postgresql://<read-only role>@<host>:5432/postgres' PG_DUMP=/path/to/pg_dump17 supabase/tests/mis_g7/prod_equivalent/capture_live_baseline_READONLY.sh`
   Produces `.local/mis-g7-prod-baseline/{catalog.json,10_schema.sql,PACKET.sha256}` — **structure only** (pg_dump `--schema-only` of `public`, `costing`, `app_private` + catalog JSON with function definitions/owners/ACLs/config for the pinned writers, the DWL editor, guards, eps, permission resolver, `auth.uid/jwt/role`, and every function touching the stock/packaging/permission tables). No row data, no user identities, no credentials. `.local/` is git-ignored; the GitHub repository is public: **never commit the packet**. `pg_dump` must be the same major version as the server (production 17.x).
2. **Run:** `MIS_G7_BASELINE_DIR=.local/mis-g7-prod-baseline node --test supabase/tests/mis_g7/prod_equivalent/mis_g7_prod_equivalent_pg.test.mjs` (needs a local PostgreSQL; prefer 17.4 via `PG_BIN`, PG16 otherwise — report any version-dependent difference). The packet is loaded into a fresh database (roles are created NOLOGIN by name only), S2 comes from the packet as the installed baseline (never replayed), S3→S5 and S5b are applied with the **real literal fingerprint pins (no seeding)**, and the accepted patched core SHA is asserted.
3. **Business-flow fixtures:** the shim-based suites (`mis_g7_pg`, `mis_g7_acceptance_pg`, `mis_g7_live_editor_pg`) use shim tables. Once a real packet exists, author `fixtures_real.sql` (synthetic rows only; columns/NOT NULLs come from the captured schema) and port those flows to the loaded database. Until then the test file ends with an explicit failing placeholder in production-equivalent mode (and a labelled BLOCKED skip in self-test mode), never a pass.
Without `MIS_G7_BASELINE_DIR` the same file runs a **PIPELINE SELF-TEST**: a stand-in database with the exact live editor and S2 is captured with the real scripts, loaded, and migrated. That proves the tooling only, **not** production parity.

## Nested FK topology (repository evidence)
26 snapshot→snapshot edges (21 unindexed, 5 indexed in the repo); parents with the widest fan-in: `cost_pool_monthly_snapshot` (6 evidenced children here; 14 inbound per S0), `sku_sales_allocation_basis_snapshot` (packing, QC, regional-expense + the acceptance FK removed by R2C), `direct_labour_component_pool_snapshot`. Every edge's both ends are purgeable in the seed; no PERMANENT/SUMMARY relation is a child of a purgeable parent (tested). The three acceptance→snapshot edges are removed by R2C (R4's `R2C_NOT_APPLIED` blocker enforces that). Child-first order is computed from the live catalog at run time (`fn_purge_order`), never from this list. Cross-run references are blocked per run (`CROSS_RUN_REFERENCE`, tested); self-referencing or cascading FKs on purgeable relations are structural blockers.

## Index decision inventory
`candidates/R4_INDEX_CANDIDATES.sql`: 21 `CREATE INDEX CONCURRENTLY IF NOT EXISTS` statements — exactly the repo-evidenced unindexed child columns of purgeable parents (completeness tested). **Not applied.** Rule: index when live child rows > 50,000 or size > 32 MB (or the child is itself purged by the same run and its run column is the access path); waive only when live shows parent and child both small (seq scan < ~50 ms), recording `index_waiver_reason`. The unindexed-child blocker refuses relations above 8 MB without index or waiver. Live decision needs PREFLIGHT_06 section C (child size/estimated rows). Operational limits: one statement at a time outside a transaction, ≥1.2× index size free, WAL headroom (live: WAL 1 GB, max 4 GB, no slots).
Run-column access paths (`WHERE refresh_run_id = $1`) are independent of the above; PREFLIGHT_06 section B reports `run_col_indexed` for every direct relation.

## Non-FK consumers
Repository-evidenced readers of purgeable relations: material acceptance (above); stage-03 refresh chain and the refresh RPCs (writers, run only for new runs); KPI / scheme-master register / pricing-profit views (read pointer-run rows); `fn_compute_run_fingerprint` / `fn_verify_run_fingerprint` (hash every run-scoped snapshot table: a purged run reports drift — acceptable because purged runs are non-approved/superseded by construction and R3B refuses verification and approval of them); exact-run readers guarded by R3B. The live reader list is PREFLIGHT_06 section D; **I did not audit consumers outside the repository** (functions created without migrations).

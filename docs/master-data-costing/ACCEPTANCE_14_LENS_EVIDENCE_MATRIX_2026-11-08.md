## 3. The eight period-switch skips (classified separately)
Cause (code): `#costingPeriodSelect` is **disabled on lenses that are not period-scoped** (`isPeriodScopedLens`, `PERIOD_PICKER_DISABLED_TITLE`) and, on PPM, hidden except for `commercial-sales-assumptions`. The runner exercised each module's **default** lens only, which in these four modules is not period-scoped, so both `selectOption` calls failed (also for the already-active 2026-11-01). The earlier "no period-label evidence" notes are therefore **not application defects**.

The only period-scoped MCM lenses are the two cost traces, which are permission-restricted for ID-V | **By design + not testable for ID-V** | none for ID-V; needs an identity with `role:material-cost-rm-trace` |
| 3-4 | CBM | `cost-governance` (`periodScoped=false`) | picker disabled by design | **By design + runner limitation** | switch the period on `manual-provisions` (period-scoped lens) or on the "Cost pool summary" / "Staff pool summary" sub-tabs |
| 5-6 | PPM | default workspace (`supportsPeriod=false`) | picker hidden except on `commercial-sales-assumptions` | **By design + runner limitation** | switch the period on `commercial-sales-assumptions` (it passed the data check in the run; the switch was not exercised) |
| 7-8 | PRM | `route-readiness` | **no PRM lens is period-scoped** (all 13 `periodScoped=false`); PRM uses an as-of date input instead | **By design: not applicable** | none needed; if desired, change the as-of date input and confirm the context banner changes |

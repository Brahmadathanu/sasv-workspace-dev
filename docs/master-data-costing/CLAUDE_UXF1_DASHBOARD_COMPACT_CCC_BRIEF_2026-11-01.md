1. Dashboard is the home for master context: selected period, approved/displayed run, valuation dates, latest successful newer draft, approval/pricing-use designation, a concise run comparison (approved 143: 627/627 READY; draft 148: 514 READY/113 REVIEW/1 BLOCKER) and CTA to investigate draft. The existing overall KPI strip must clearly identify its approved/governed run and MUST NOT appear to switch to draft while displaying 143 metrics.
2. Header: replace long orange 'Approved run 143 (newer DRAFT run 148 - not approved)' with compact status 'Approved 143' or equivalent plus a small discoverable newer-draft indicator (e.g. 'Draft available'), whose full explanation resides on Dashboard. Responsive portrait cannot wrap into multiple rows or obstruct refresh, export or Home. Preserve existing run-status controller semantics, accessibility and data provenance.
3. Worklist: compact run picker and issue list, proper visual card/table hierarchy. Default view shows at most one short status line, one concise run context, and grouped exceptions (severity + label + SKU count + single primary action). Place frozen-run and drawer-evidence caveats behind an accessible contextual disclosure, BUT keep a brief visible warning when draft is selected that drawer evidence is not draft evidence. Replace long raw text paragraphs, redundant badges and duplicated note lines with concise copy. Use existing stylesheet conventions; inspect whether C1 worklist lacks CSS definitions and add scoped CSS (not inline CSS sprawl). Preserve keyboard access and screen-reader labels, colour-independent severity, mobile width and touch targets.

The existing Readiness tab is NOT to be modified into a new data source in this immediate package.
5. Preserve ALL existing actions: search, filter, rows/table, period switch, read-only run selection, table/drawer and fix-screen navigation, export, permission gating, asynchronous request generation, flag-off behaviour, and draft semantics.

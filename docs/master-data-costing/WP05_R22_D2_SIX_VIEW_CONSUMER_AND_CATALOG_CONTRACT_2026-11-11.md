## Focused view-predicate readback (11 November 2026, later than initial R22)

A second **catalogue-only** `pg_get_viewdef` query examined the trailing SQL for all six. Each definition ends with `WHERE (SELECT fn_costing_view_allowed())`. This places the four-module helper as an actual outer view predicate, rather than merely a mentioned dependency. The sampled tails do not establish whether every underlying source contains independent restrictions, but show no *additional outer restriction* at that final level. In particular `v_costing_scheme_master_audit` reads `costing.scheme_master_audit` and applies this helper, while the helper does **not** test `module:pricing-policy-manager` View. It has authenticated SQL SELECT and is not security-invoker. **Escalated source-level policy-contract risk:** a legitimate PPM-only viewer could be denied, and a viewer with an unrelated one-of-four Costing View grant could satisfy the outer predicate. This is not yet actual authenticated end-user outcome or demonstrated unauthorised row disclosure. It requires exact permission oracle and safe isolated role verification before determining whether a security correction is closure-critical. No actual view rows or user accounts were read/changed; issue #297 contains this finding.

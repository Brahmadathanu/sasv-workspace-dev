# Period lifecycle design (draft migration supabase/migrations_draft/20261016100000; local tests 7/7)
Findings: rpc_ensure_cost_period (insert-if-absent, SYSTEM_DEFAULT/DRAFT, audited) exists but nothing schedules it; refresh functions only read periods → no Oct row ⇒ job 60 returns CURRENT_PERIOD_NOT_GOVERNED. fn_default_cost_period_valuation_date: past→month end, future→month start, current→today (frozen at creation). Client: public/shared/js/costing-suite-cost-period-valuation-helpers.js reads rpc_get_cost_period_valuation_context; manual changes via rpc_set_cost_period_valuation_date (GOVERNED_MANUAL).
Design: effective-dated costing.cost_period_lifecycle_policy (default all flags OFF) + costing.fn_cost_period_lifecycle_tick(business_date): ensures current month (idempotent), advances valuation date only for OPEN/DRAFT/SYSTEM_DEFAULT periods with no designation; never touches LOCKED/CLOSED, GOVERNED_MANUAL or REFERENCE/APPROVED-designated periods; audited. Rollover is implicit (new business month ⇒ new row; prior month stays OPEN until governed lock/close).
Integration: job 60 → tick → request (graceful PERIOD_HOLDS_APPROVED_RUN) → job 61 unchanged; AU-2 guards remain the backstop. Activation = policy row approval (no code change). October not opened.

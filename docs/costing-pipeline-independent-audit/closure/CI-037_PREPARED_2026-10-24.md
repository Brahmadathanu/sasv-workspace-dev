## Design change in v2 (found while capturing evidence)
Run 119 (REFERENCE) has a legacy fingerprint capture with no column list. For such captures `fn_verify_run_fingerprint` re-hashes **all current columns** of the table. v1 added columns to `sku_pricing_bridge_snapshot`, which would have shown fingerprint drift on run 119. This was reproduced in the local test (T1). v2 therefore leaves that table's columns alone (it gets comments only). It stores the chain in a new side table `costing.sku_pricing_bridge_profit_snapshot`, with one row per SKU and region:
- The name matches `fn_costing_run_scoped_tables()`, so future fingerprints include it.
- Old runs have 0 rows in it and are skipped by the verify function.

## ChatGPT items → where addressed
1. **Hook.** The fix counts the anchor and the hook. With 0 hooks it inserts one. With 1 correctly placed hook it does nothing. With 2 or more, or a misplaced hook, it raises an error (tests T5–T8). Rollbacks remove the hook only when exactly one is present.
2. **Validation.** The helper returns explicit codes: MISSING_UPSTREAM_STATUS, UPSTREAM_BLOCKED, UNKNOWN_UPSTREAM_STATUS, SCHEME_BLOCKED_OR_MISSING, MISSING/INVALID_MRP, MISSING/INVALID_GST, MISSING/INVALID_BASIC_PRICE (checked against MRP/(1+GST) to ±0.01), MISSING/INVALID_DISCOUNT, MISSING/INVALID_SELLING_PRICE (checked against basic×(1−disc)), MISSING/INVALID_SCHEME_QUANTITY (paid>0, free≥0, whole numbers, total=paid+free), MISSING_CONTINGENCY, CONTINGENCY_NOT_ON_SELLING_PRICE, MISSING/INVALID_REGIONAL_MARKETING and MISSING/INVALID_COST.
   - Upstream REVIEW_REQUIRED gives CALCULATED_UPSTREAM_REVIEW.
   - Values are NULL unless the status starts with CALCULATED, and a CHECK constraint enforces this.
   - Run 143 dry run with this logic: all 1,254 SKU-region rows are CALCULATED (23 with a loss).
3. **Immutability.** `trg_au2_designated_run_guard` calls `costing.fn_guard_designated_run_rows()`. That function raises `AU2_DESIGNATED_RUN_IMMUTABLE` on INSERT, UPDATE or DELETE when the run's designation is REFERENCE, APPROVED or REVOKED (read live). The fix attaches it, plus `trg_au2_snapshot_truncate_guard`, to the new table. The helper refuses the same designations. Tests T9 and T10 confirm. Live designated runs: 119 REFERENCE, 122 and 143 APPROVED, 128, 136 and 140 REVOKED.
4. **Cardinality.** The helper raises an error, so nothing is written, if any of these fail:
   - one pricing-bridge row per SKU;
   - selling-price rows equal to pricing-bridge rows, one per SKU;
   - exactly one IK and one OK selected-scheme row per SKU;
   - after insert, exactly 2×SKU rows with no missing SKU-region pair.
   Tests T14 and T15 confirm.
5. **Snapshots.** The chain function and view texts were captured. The view has **64** columns. CURRENT_STATE, CHANGELOG and the feed contract are corrected (they said 65).
6. **View metadata.** Owner postgres. relacl NULL, but effective privileges were captured explicitly: anon, authenticated and service_role have none; postgres has all. reloptions NULL (no security_invoker). No dependent views and no function references. 22 column comments. No default ACLs in schema `costing`. Rollback A recreates all of this and asserts it (T22).
7. **Rollback split.** Rollback A is guarded and structural. Rollback B is non-destructive. Tests T17–T22 cover both.
8. **Fingerprints.** The before-evidence was read live. Of 303 table checks across the 6 designated runs, 302 match. The one mismatch (run 119, `sku_sales_allocation_basis_snapshot`) **already existed** before CI-037 and needs separate review. The aggregate md5 is recorded, and verify requires it unchanged after apply.
9. **Open facts (nothing changed).** See below.
10. **Sheets.** See CI-037_SHEETS_RECONCILIATION_SPEC.md.

## 9. Facts, documented only
- **Packing & Forwarding Charges (DE):** mapped to MATERIALS_STORES_OVERHEAD (Direct Expenses, remark "Packing / forwarding support expense"), so it sits inside the internal loaded cost. The name suggests outward despatch. If it is outward selling or distribution, it belongs with Carriage Outward in MARKETING_EXPENSE, and today's figures would carry it in the cost per pack instead. **Owner or Finance to classify. Not changed.**
- **Free packs in the sales denominators:** costing volumes come from `public.sales_monthly.qty_units` (via `fn_costing_sales_monthly_as_of`), not `qty_billed`. Over the last 12 months, units exceeded billed by 147,531 packs (2,135,837 vs 1,988,306, or 6.9%), on 7,473 of 16,998 rows.
  - That pattern fits free (scheme) packs being included, so per-pack overheads are spread over delivered packs. This is consistent with the per-delivered-unit profit method.
  - Not proven: the difference could also include samples or replacements. The source (`app_private.sales_monthly`) was not traced further.

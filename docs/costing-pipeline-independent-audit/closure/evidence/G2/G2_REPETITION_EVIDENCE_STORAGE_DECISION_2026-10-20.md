# G2 decision: durable repetition evidence without a new table

Read-only schema audit on 20 October 2026 shows neither `costing.production_route_family_route` nor `costing.product_process_route` currently has a JSON/JSONB column. Their generic `approval_reference`, `route_note`, `approved_by`, and `approved_at` are insufficient for count-specific proof. Costing-wide fingerprint and review records relate to other workflows and must not be repurposed without a documented ownership contract.

**Minimal design candidate, not yet implemented or approved:** add one nullable JSONB `repetition_approval_evidence` field to each of the two existing route headers (two columns; no new tables). Only the existing governed approval transaction may set the value, and only if dual-positive route steps exist. The value must contain a format version, exact route ID and route_version, canonical ordered step IDs/keys with occurrences, cycles and computed total, deterministic digest of the whole effective step set (including product overrides), approver UUID, and confirmation timestamp. Construct/verify values server-side against currently locked route contents; do not trust a caller-supplied digest. A changed step count, effective step list or route version must invalidate the confirmation. Existing history stays nullable, with current approved route 144 untouched. Changes must be blocked outside the governed approval transaction through permissions or policy, not merely the UI.

Crucial implementation decision still required: determine transaction-safe locking of **step rows** and review workflow edits during approval, including product effective-route resolution. Header FOR UPDATE alone is not proof that step edits cannot race. Inspect existing route-step mutation RPCs/permissions before writing migration. Do not deploy, alter current functions, or infer enforcement from client warnings.

Required tests: 8x1 and 1x8 unaffected; new 8x8 without full acknowledgement rejected; exact 8x8 confirmation accepted only with all other validators passing; stale step/revision rejected; route family and product route both covered; old APPROVED routes remain readable; protected runs 122/128 unchanged. G2 OPEN.

## Owner-approved KYC lifecycle (28 November 2026)
- Every debtor (Tally receivable ledger, not procurement creditor/vendor) must have a complete ACTIVE KYC to clear the consolidated Management Alert. New, unmapped, draft, inactive and invalidated current debtors remain visible in Finance and in the alert. Historical zero-balance identities remain in the register but do not flood current exposure alerts.
- Lifecycle: DRAFT (default), ACTIVE, INACTIVE. Save persists incomplete draft without activation. Activate enabled only for authorized editors when server validation returns no missing/invalid fields. Inactivate enabled only for ACTIVE records; require reason. Reactivate uses same full validation. No deletion, financial exclusion or ledger status change. Activation is KYC status only, distinct from commercial/customer trading eligibility.
- Each applicable KYC field must be explicitly completed: value, NA (not applicable) or NIL (applicable but none). Blank/unanswered is incomplete. Use structured dispositions, not magic strings in numeric/foreign-key fields. Mandatory identity, region, godown, district, debtor type, primary address and at least one valid contact cannot be bypassed by NA/NIL. Area may be NA if district has no applicable subdivision; optional alternate phone, email, address line 2 and GSTIN can be explicitly NA/NIL as appropriate. GSTIN NIL/NA requires reason; never imply tax exemption. Commercial discount NIL means explicit 0%; scheme NIL means existing No Scheme; inheritance is separate and only complete when resolved. Notes may be NIL. Country/state/postal details required where applicable; outside-India exceptions require documented reason. This field matrix is a proposed operational default pending SASV-specific refinements.
- Server recomputes readiness at activation and on effective reporting; inactive master/expired or missing terms/invalid hierarchy cannot count as valid ACTIVE KYC. Editing an active record may retain ACTIVE only if all invariants still pass; otherwise explicitly inactivate first, preserving audit. No silent demotion. Status changes, saved revisions, actor, timestamp, reason and validation evidence audited; optimistic revision and transaction locking required. Never expose PII in alert or general reporting.
- Finance KYC modal: Save, Activate, Inactivate controls with server-derived eligibility and inline missing-field checklist; NA/NIL controls only where applicable. Read-only users cannot save or transition. Alerts deep link to current debtors without valid ACTIVE KYC, including outstanding amount and counts by reason; resolve automatically once valid active record exists. 
- Acceptance: incomplete Save succeeds; incomplete Activate denied even via RPC; explicit applicable NA/NIL passes; invalid NA/NIL denied; complete Activate succeeds; stale revision denied; Inactivate requires reason and reopens alert; reactivation validates afresh; current report totals unchanged throughout; no access and view-only mutation attempts denied. Test commercial expiry and master deactivation as effective completeness failures.

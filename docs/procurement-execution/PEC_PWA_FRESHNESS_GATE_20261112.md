# PEC installed-PWA freshness — focused release gate (12 Nov 2026)

**Context:** PEC ERP client work is staged in stacked draft PRs #291 → #301 → #320 → #335, and uses shared canonical `/shared/js/procurement-execution-console.js`, `/shared/css/sasv-procurement-execution-console.css`. The service-worker `public/sw.js` currently sends unrecognised static JS/CSS cache-first, even when HTML is newly served network-first. An installed PWA could pair updated HTML with obsolete PEC JS, retaining old full-read RPCs and broken paging logic after the server functions change.

**Correction:** Route those exact canonical PEC JS and CSS paths through the existing **network-first, `cache:'no-store'`, offline cached fallback** handler. No service-worker cache-name/version change (`hub-cache-v393`), no broad asset glob, no changes to Supabase, server SQL, procurement records or Electron source. The Electron and PWA continue to share one canonical module.

Both job steps `PEC installed-PWA freshness` and `Existing FG-BIT SW freshness non-regression` passed. This confirms mocked-SW testing under CI, **not** real installed-PWA browser acceptance.

## Client integration contract (for the later single excess-modal package)
`public.mis_pack_fg_bulk_v1(p_request_id uuid, p_packaging_event_id int, p_lines jsonb, p_excess jsonb default null) -> jsonb`
- `p_lines`: `[{"sku_id":int,"count":int>0}]`, unique sku_id. `p_excess` (only after an `INSUFFICIENT_BULK` with `excess_permitted:true`): `{"qty_base":number>0,"evidence_ref":text,"reason":text}`; any other key (e.g. "authorized") is ignored.
- Retry with the same `p_request_id` and payload returns the stored result with `idempotent_replay:true`; same id, different payload → `IDEMPOTENCY_KEY_REUSED`. Generate a UUID per user intent.
- Success: `{ok:true, idempotent_replay, request_id, product_id, batch_number, packaging_event_id, required_base, available_before_base, excess_base, excess_id, balance_after_base, base_uom, event_sku_ids[]}`.
- Refusal (HTTP 200, `ok:false`, nothing written): `INVALID_INPUT, IDEMPOTENCY_KEY_REUSED, PACKAGING_EVENT_NOT_FOUND, BATCH_IDENTITY_MISSING, EVENT_NOT_BULK_AFFECTING, EVENT_NOT_DEPLETING, FG_STAGE_NOT_SIGNED (+historical_state NOT_VERIFIED), FG_RECEIPT_MISSING, SKU_NOT_FOUND, SKU_PRODUCT_MISMATCH, SKU_PACK_SIZE_INVALID, SKU_CONVERSION_INVALID, SKU_LINE_EXISTS, INSUFFICIENT_BULK {required_base, available_base, shortfall_base, base_uom, excess_permitted}, INSUFFICIENT_AFTER_EXCESS, EXCESS_INVALID, EXCESS_NOT_AUTHORIZED, EXCESS_NOT_NEEDED`.
- Raised errors: SQLSTATE `42501` permission denied / `MIS_G7_AUTH_REQUIRED`; `MIS_G7_DEPLETION_MISMATCH`, `MIS_G7_NEGATIVE_BALANCE` (whole transaction rolled back).
- Signer: `mis_sign_batch_stage_v1(p_idempotency_key uuid, p_product_id int, p_batch_number text, p_work_log_id int, p_route_step_id bigint, p_step_occurrence int, p_measured_qty_base numeric, p_evidence_ref text)`; codes `PRODUCT_ROUTE_COVERAGE, EFFECTIVE_DATE_ROUTE_GAP, APPROVED_ROUTE_OVERLAP, MANDATORY_FG_STAGE_GAP, BMR_IDENTITY_REVIEW, WORK_LOG_IDENTITY_MISMATCH, STEP_NOT_IN_EFFECTIVE_ROUTE, ACTIVITY_STEP_MISMATCH, MEASURED_QTY_REQUIRED, STAGE_ALREADY_SIGNED, IDEMPOTENCY_KEY_REUSED`. Correction: `mis_correct_batch_stage_v1(key, event_id, reason)`.
- UI: no theme palette dependency; legacy direct writes remain for old clients.

## Known limits (unresolved)
- force-close/auto-zero still read balance before locking (no live bodies to wrap): under a race they fail closed (negative guard), never over-draw.
- Multi-row ledger statements touching batches in opposite orders can deadlock; PostgreSQL aborts one fully (tested).
- ENFORCE blocks legitimate direct SKU corrections and the governed DWL-update RPC's packaging writes until a correction RPC / ticketed integration exists; do not flip until then.
- Permission targets unregistered live; role assignment owner-authorized.

## Review round 2 (head 9d6f249 -> this commit)
- **P0** helper EXECUTE bypass closed (see migration 4 above); tests assert no client role (authenticated ordinary/packer/excess/nobody, anon, PUBLIC) can execute any stock-writing legacy function, plus a catalog allowlist guard: the only client-executable SECURITY DEFINER functions touching the ledger are `fn_fg_force_close(int,text)`, `mis_pack_fg_bulk_v1`, `mis_sign_batch_stage_v1`.
- **citext**: `packaging_events.event_type` is CITEXT live. ## Review round 3: reconcile chain (head e938b557 -> this commit)
Live chain (independent READ ONLY review): `trg_fg_ledger_reconcile_{ins,upd,del}_stmt` (statement-level, INVOKER, authenticated EXECUTE) -> `fn_fg_reconcile_batch` (INVOKER, EXECUTE postgres+service_role only) -> `fn_fg_auto_zero`, then guarded transaction-local Done marking. The round-2 precheck correctly refused to install because the reconciler references `fn_fg_auto_zero`.
- **Resolution (S3b, no bypass of the precheck):** the *resolved graph* is validated, then the whole chain (six writers + reconciler + 3 statement triggers = 10 functions) is converted to SECURITY DEFINER with pinned `search_path` (bodies unchanged), EXECUTE is revoked from PUBLIC/anon/authenticated on every member except the reconciler, whose ACL is left exactly as is (and the install refuses if it is already client-executable). Automatic reconciliation, epsilon auto-zero and the Done transition therefore run in owner context for every writer; clients still cannot call any privileged helper.
- **Fail-closed install checks:** all ten exist and have a pinned search_path; the nine supplied live `pg_get_functiondef` SHA-256 values still match (`app_private.mis_g7_s3b_expected_sha`; the reconciler SHA was not supplied and is only captured); the three reconcile triggers are installed statement-level ledger triggers; no *other* invoker function references `fn_fg_ledger_add`/`fn_fg_auto_zero`/`fn_fg_reconcile_batch`. `S3B_PREINSTALL_LIVE_CHECK_READONLY.sql` runs the same verification read-only against production.
- **Immutable packet:** the baseline now persists the full pre-change `pg_get_functiondef` text and SHA of all ten functions plus ACL/secdef/config; rollback restores attributes from it and the test proves identical SHA/ACL/config/secdef after rollback for the whole chain. A separately retained packet of the live function sources remains a deployment prerequisite.
- **Test-schema honesty:** shim chain bodies are reconstructions of the described behavior (Done guard flag name `mis.fg_reconcile` is an assumption); they cannot hash to the live SHAs, so the harness pre-seeds the expected-SHA table with the shim's own hashes while dedicated tests prove (a) the migration pins the supplied literal SHAs, (b) literal SHAs refuse a non-identical schema, (c) a mutated function refuses install.
- **Observed nuance:** pre-S3b a direct *authenticated* ledger write fires the INVOKER statement trigger as the client and is denied at the reconciler (shim reproduces this); writes through definer RPCs/triggers run as owner. After S3b all paths run in owner context.
- **Known residual:** the Done guard relies on a transaction-local setting; any role able to call `set_config` can set a custom GUC, so it is a procedural guard, not an authorization boundary (pre-existing design; not changed here).

## Review round 4: `fn_fg_mark_done_if_zero` (live caller of the reconciler)
The pre-install READ ONLY run against production (11/12) found one more actual caller of the reconciler: `fn_fg_mark_done_if_zero(integer,text,numeric)` (SECURITY INVOKER, authenticated + service_role EXECUTE, pinned `search_path`, SHA-256 `278f4fdc…cb6a`). Live fingerprint of `fn_fg_reconcile_batch` is `b229faad…7be`; both are now pinned (11 pinned functions) and included in the baseline (11 rows, full source + SHA) and in `S3B_PREINSTALL_LIVE_CHECK_READONLY.sql` (15 rows). The function is *not* excluded from the graph scan: the scan now also treats `fn_fg_mark_done_if_zero` as an entrypoint, so any other invoker function referencing it refuses the install.
- **Why not just DEFINER with client EXECUTE:** any authenticated caller could then trigger stock auto-zero with a caller-chosen epsilon. **Why not just revoke:** it would break the existing authorized "Done when zero" capability (no client call site in this repo: only generated types mention it; DB-side callers are covered by the scan).
- **Resolution (S3b):** the proven body is renamed to `fn_fg_mark_done_if_zero_legacy` (SECURITY DEFINER, EXECUTE owner + service_role only) and the original name/signature/void return is re-published as a narrow SECURITY DEFINER wrapper: (a) trusted path = the actual database role `service_role` (`current_setting('role')`, not forgeable by non-members; a forged JWT-claim GUC grants nothing, tested), otherwise `auth.uid()` required plus canonical `require_permission('module:daily-work-log', true)` (superseded by round 5 below); (b) caller epsilon bound (superseded by round 5 below); (c) takes the product/batch lock first; (d) no signing/excess/receipt capability and no change to the transaction-local Done flag.
- **Rollback:** drops the wrapper only if it carries the S3b marker, renames the legacy function back, then the baseline loop restores secdef/search_path/ACL; test proves the original name, SHA and exact legacy behavior (denied at the reconciler for authenticated) return.
- **Tests (new):** structure/ACLs; authz matrix (nobody, signer-only, pack+excess-only, anon, no-subject authenticated, direct legacy call, forged role/sub claims); authorized behavior (zero→Done, dust→AUTO_ZERO+Done, stock untouched, eps 0); epsilon cap and invalid input; service_role trusted path; concurrency with a packer holding the batch lock; graph-precheck refusals (invoker caller, SHA mismatch/unpinned, pre-existing legacy name); read-only script execution.

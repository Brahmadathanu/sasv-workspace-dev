## 3. What ENFORCE needs, and what this package adds
ENFORCE denies direct bulk-affecting `event_skus` INSERT/UPDATE/DELETE and header reassign/retype/delete unless made by a ticketed RPC in the same transaction. Governed alternatives now exist for both write paths: `mis_pack_fg_bulk_v1` (new lines, with measured excess) and `mis_correct_pack_line_v1` (change count / remove a line, with measured excess when a correction increases consumption beyond stock). A correction never fabricates stock: a line without its original depletion (e.g. the historical 29 missing-depletion lines) or with a tampered ledger is refused (`CORRECTION_NO_DEPLETION_BASIS` / `CORRECTION_LEDGER_MISMATCH`); batches without a signed, un-drifted FG stage are refused (`FG_STAGE_NOT_SIGNED` / `STAGE_SOURCE_CHANGED`, `historical_state: NOT_VERIFIED`). Mode changes go through `mis_g7_set_enforcement_v1` (separate admin permission, reason required, append-only log; ENFORCE refused if the correction path is missing); `mis_g7_enforcement_readiness_v1` reports direct legacy writes captured by AUDIT logging so the owner can see whether old clients still write directly. Default remains **AUDIT** (old clients unchanged, direct writes logged with actor/op/txid).

## 3b. Legacy governed editor (`rpc_update_daily_work_log_with_packaging` + `__core` + `fn_parse_sku_breakdown`) — S5 / S5b
**Exact live source** is retained in `LIVE_DWL_EDITOR_REFERENCE_ONLY_20261124.md` and is what the editor tests install (they assert the installed text hashes to the production SHA-256 values: wrapper `4c82b4a3…d7b4`, core `df7290df…6aec`, parser `ec5fe3ea…29db`). Live behavior (from that source): the wrapper checks `module:edit-log-entry` (edit), validates FG source identity/UOM/location immutability, computes a single FG source-quantity delta, sets transaction-local flags (`app.fg_reconcile`, `app.allow_dwl_fg_qty_correction`), calls the core, posts the correction ledger row (`created_by` = JWT email/uid) and reconciles. The core locks the work log, UPDATEs it, and for Done packaging rows **deletes the old `event_skus` then the header and recreates header + lines from `sku_breakdown`** (`<pack_size> <uom> x <count>` segments separated by `;`, matched to `product_skus`); rows that stop being Done packaging have the chain deleted.
- **Minimal protected integration (S5b, owner-gated, NOT installed):** the core is replaced with the exact live text plus one function-local directive and three statements (`LIVE_DWL_EDITOR_CORE_S5_PATCH.diff`): `mis_g7_chain_replace_begin(p_id, p_item, p_batch_number)` right after the row lock (before any write; it locks the old AND the new item/batch identity in one canonical sorted order, so opposite moves cannot deadlock) and `mis_g7_chain_replace_finish(p_id)` before each of the two exits. Wrapper, parser, signature, security attributes, search_path, owner and ACL are unchanged. Patched core SHA-256: **`dfa5a5e9aa31b48cf41fe9d03800fff2e35e5a3825ca458b5ccb6ca6c4471bcc`** (pinned in the migration, which refuses to commit on any other result, and refuses to run unless the live core/wrapper/parser still hash to the reviewed values).
- **What S5 verifies (identity-aware):** begin = batch lock + a ticket scoped to that work log and transaction. **Mode-dependent:** under ENFORCE every violation raises and rolls the whole edit back; under AUDIT (default) violations are only RECORDED in the append-only audit log (`tbl='chain_replace'`, op = violation code, detail, actor) and the legacy behavior proceeds unchanged — so installing S5b does not block today's editing of unsigned/historical batches. Finish, atomic with the edit: signed, un-drifted FG stage for every identity touched (old identity when the old chain was bulk-affecting, new identity when the new chain is), **FG stock conservation per identity** (ledger movements of all old+new lines net to exactly the new depletion; when the DWL item/batch changes the old identity must net to 0 and the new to the new depletion), balance ≥ 0, and a deferred trigger refuses to commit an unfinished ticket. Consequences found with the real source: (a) a never-depleted historical line (the 29-class) cannot be edited/removed through the editor under ENFORCE — the legacy trigger would return stock never consumed (refused: `MIS_G7_CHAIN_CONSERVATION_MISMATCH`; in AUDIT the +stock hazard still happens and is recorded); (b) moving a packaging row to another batch in one edit mis-assigns stock under the legacy core (documented by test) and is refused by S5; (c) after an old FG receipt revision the stage has drifted, so further chain edits and the new RPCs refuse until the stage is corrected and re-signed.
- **AUDIT (default): behavior preserved.** The same edit script yields identical lines/balances/status on the original and the patched core (create, two-segment replace, retype, chain removal, recreate, re-edit; FG source corrections and non-packaging edits untouched). Direct writes stay logged.
- **ENFORCE fails closed:** refused (`LEGACY_DWL_EDITOR_NOT_FOUND` / `…_NOT_MIGRATED` / `CORE_MIGRATION_NOT_ACCEPTED`) unless the live core calls both primitives and the owner has signed off the core's exact SHA-256. Marker text alone is not treated as proof: behavior is enforced by the deferred must-finish trigger, the ticket scoping and the tests; the sign-off binds the exact text.
- **Variable resolution (no setting change):** the live default is `plpgsql.variable_conflict = error`. The live core has an OUT column `packaging_event_id` and two unqualified `WHERE packaging_event_id = v_old_packaging_event_id` references to the `event_skus` column, which are *ambiguous* under `error`. The patch therefore adds the function-local directive `#variable_conflict use_column` (the evident intent; no server/database/role change; the wrapper is unaffected). **Owner decision:** on the live default, replacing/removing an EXISTING chain through the editor raises today (tests show the ambiguous-column error and full rollback); after S5b it works as written. Verify on production whether any role/database override exists (CORE read-only script row 3 reports the value observed).
- Verify before any core change: `CORE_PREINSTALL_LIVE_CHECK_READONLY.sql` (core SHA, ACLs, delete/recreate present, setting, unmigrated).

Rules for clients: one UUID per user intent; show the excess modal only after `INSUFFICIENT_BULK` with `excess_permitted:true`; never send authorization flags; treat `idempotent_replay:true` as success; retry only on SQLSTATE `40P01`/`40001`; raised errors (`42501`, `MIS_G7_*`) mean the whole transaction rolled back; no hard-coded theme palette is implied.

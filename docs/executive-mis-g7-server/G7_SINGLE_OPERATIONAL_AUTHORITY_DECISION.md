# G7 operational authority — owner decision, 24 November 2026

Status: G7 OPEN 7/11; G8 parked. Applies to draft PR #526, baseline 61764933997d6e581690a8381d7df362ed0c80cb. PEC release independent.

## Binding direction
No new version-suffixed RPC names. No parallel operational routes. One source of truth. Existing Add Log Entry, Edit Log Entry and Update Log Status are UI entry points to the same server authority, not competing transaction engines. Batch Governance is a supervisory view and uses the same commands when authorized. Do not force operators to create a legacy packaging chain and then post the same quantities again.

Existing deployed API signatures must remain compatible until old supported clients are retired; compatibility wrappers are adapters only, not independent implementations. Do not rename or replay the eleven installed migrations. Distinguish migration identity/version history from business API naming. No new _v1/_v2 suffixes. Existing versioned MIS functions should converge on canonical unversioned authority with thin adapters as necessary, not be cloned.

## Bounded implementation
1. Audit the existing create/update/status wrappers, private cores, S5b chain tickets, S7 exact receipt helper, packer/correction writer, preview and all client call sites. Include status transitions, not just Add/Edit.
2. Implement one canonical packaging transaction for create or complete, using the existing depletion authority (refactor it into one private core if necessary). Existing wrappers dispatch to it when governed operation is required. Legacy AUDIT compatibility is temporary, explicitly controlled and not a second permanent governed route. No silent fallback after governed refusal. Preserve non-bulk packaging/Transfer to FG Store and ordinary production logging.
3. One shared preview calculation used by the posting authority and operator preview. Revalidate under the batch lock. No fake preview header or stock movements. Use exact SKU identities and counts, source-specific signed FG receipt, measured excess only when required and authorized. Create/complete/header/lines/excess/depletion are atomic; domain refusal after intermediate mutation rolls back the entire attempted operation. Request identity binds actor, operation and normalized complete payload; exact replay returns original receipt before creating another header. Use one documented lock order; concurrent legacy/modern writers must not bypass protection.
4. Existing editor routes safe non-stock metadata through a narrow allowlist (initially remarks); no packaging-chain reconstruction. Preserve ledger, IDs, fingerprints and status. Reject stale writes and unknown fields. Structural identity, signed evidence, counts and location remain governed by their existing appropriate authorities. Ensure displayed SKU summary is consistent with authoritative event_skus after correction; no independent editable breakdown truth.
5. Resolve the status writer's destructive Done/Doing path as part of the same authority. No generic deletion/rebuild of governed evidence. Preserve AUDIT operation for currently deployed clients; explicitly document cutover prerequisites and how bypasses are closed before ENFORCE.
6. Single shared client interaction for Add/Edit/Update Status, including in-page preview and measured excess, persistent signature state, retry and corrections. Batch Governance calls the same server authority. No duplicate submission or mandatory cross-module re-entry. No new permanent activation path; existing flag remains off until acceptance.
7. WP10 S4/S6 narrow reviewed approved delta only. Preserve PEC and Costing guards. Reconcile against post-PEC stable main only when that release is complete. Do not touch PEC release configuration in this package.
